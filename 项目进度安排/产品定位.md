# 银龄澳门本地生活 Agent 产品定位

## 产品名称

银龄澳门本地生活 Agent

## 一句话定位

面向长者和陪同家属的澳门本地生活 Agent，根据长者体力、兴趣偏好、饮食需求、无障碍条件和交通便利度，规划低疲劳、可解释、可执行的本地出行方案，并通过 Qwenpaw 协助完成预约、订位和点单。

## 目标用户

- 有澳门本地轻松出行需求的长者
- 陪父母、祖父母出行的子女或家属
- 希望减少路线查询、餐厅选择、预约订位操作负担的陪同者

## 核心场景

长者或家属输入一句自然语言需求，例如：

```text
我想带爸妈下午轻松逛逛，不想爬楼梯，最好有地方坐，晚上吃点清淡的。
```

系统需要完成：

1. 理解长者出行限制和偏好
2. 筛选适合长者的景点和餐饮点
3. 规划低疲劳、少台阶、交通方便的路线
4. 解释为什么这样安排
5. 用户确认后，通过 Qwenpaw 协助预约、订位或点单

## 产品目标

本项目不是单纯生成旅游攻略，而是完成一个从需求理解到生活服务执行的闭环。

核心目标包括：

- 帮助长者减少出行决策成本
- 帮助陪同家属快速安排合适路线
- 避免高疲劳、高台阶、暴晒、路线复杂等风险
- 将景点、交通、适老化和餐饮数据转化为可执行决策
- 通过 Qwenpaw 将规划结果进一步落到预约、订位和点单动作

## 产品能力

### 1. 长者需求理解

系统需要识别用户表达中的长者出行条件：

- 是否需要避免楼梯
- 是否需要减少步行
- 是否需要无障碍厕所
- 是否需要休息点
- 是否偏好室内或遮阴环境
- 想去什么区域
- 想做什么活动
- 想吃什么类型的食物
- 是否需要预约、订位或点单

### 2. 长者友好路线规划

系统需要基于数据生成适合长者的路线，而不是只按热门程度推荐。

路线规划应重点考虑：

- 区域是否顺路
- 步行距离是否可接受
- 台阶和斜坡风险是否较低
- 是否有休息点
- 是否有无障碍厕所
- 是否有室内/冷气休息空间
- 交通是否方便
- 下车后路线是否复杂
- 餐饮是否适合长者

### 3. 可解释推荐

每条路线都需要说明推荐依据。

解释内容应包括：

- 为什么适合长者
- 哪些地方不累
- 哪里可以休息
- 有没有厕所、电梯、坡道或扶手
- 下车后怎么走
- 有哪些风险需要注意

示例表达：

```text
这条路线适合长者，因为主要在室内，步行距离短，中途有休息点，也有无障碍厕所；系统避开了台阶较多和暴晒路段。
```

### 4. Qwenpaw 执行协助

Qwenpaw 在本项目中定位为执行层助手。

它主要负责：

- 根据用户确认后的路线协助预约
- 协助餐厅订位
- 协助点单
- 返回执行结果
- 在失败时提示原因或触发备选方案

Qwenpaw 不负责主要规划逻辑。规划、评分和解释由本项目 Agent 完成，Qwenpaw 负责把确认后的计划转化为实际操作。

## 系统整体流程

```text
用户输入长者出行需求
→ 需求解析
→ 匹配适老化数据和交通数据
→ planner 生成候选路线
→ scorer 给路线评分
→ explainability 生成推荐理由和风险提示
→ 用户确认
→ executor 组织执行任务
→ Qwenpaw 协助预约、订位、点单
→ 返回执行结果
```

## 报告中的核心叙事

本项目围绕银龄群体的本地生活需求展开。

长者出行不仅需要知道“去哪”，还需要考虑“是否走得动、是否安全、是否方便休息、是否有厕所、交通是否简单、能否顺利预约和就餐”。因此，本项目将澳门景点、适老化、交通和餐饮执行数据结合起来，通过 Agent 完成从理解需求、规划路线、解释原因到执行预约点单的完整流程。

## 预期展示案例

### 案例 1：陪父母轻松出行

```text
我想带爸妈下午轻松逛逛，不想爬楼梯，最好有地方坐，晚上吃点清淡的。
```

展示重点：

- 识别长者、低疲劳、避免楼梯、需要休息点、清淡饮食
- 生成低疲劳路线
- 解释推荐依据
- Qwenpaw 模拟订餐或预约

### 案例 2：行动不便长者

```text
爷爷行动不太方便，想去澳门半岛附近看看展览，路线不要复杂。
```

展示重点：

- 识别行动不便
- 优先选择室内、少台阶、路线简单的地点
- 展示交通和下车后步行指引

### 案例 3：吃喝休闲为主

```text
奶奶不想走太多，想喝茶吃点心，顺便附近轻松逛一下。
```

展示重点：

- 识别饮食偏好
- 规划短路线
- 安排茶点或餐厅
- Qwenpaw 模拟点单或订位
