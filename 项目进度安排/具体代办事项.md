# 具体代办事项

## 一、报告内容整理

### 1. 明确项目定位

- [ ] 在报告开头写清产品名称和一句话定位
- [ ] 说明目标用户是长者和陪同家属
- [ ] 说明项目解决的是长者本地出行、餐饮、预约和点单中的决策与执行问题
- [ ] 梳理完整项目流程：需求输入 → 数据匹配 → 路线规划 → 推荐解释 → Qwenpaw 执行

### 2. 问卷需求分析

- [ ] 整理问卷结果中的核心发现
- [ ] 提炼长者出行痛点，例如：怕累、怕楼梯、怕路线复杂、需要厕所和休息点、希望有人协助预约订位
- [ ] 把问卷结论和产品功能对应起来
- [ ] 做 2-3 张图表，用于报告展示

### 3. 数据说明

- [ ] 说明项目使用了哪些数据表
- [ ] 说明每类数据在 Agent 中的用途
- [ ] 说明数据清洗目标：让数据可以被筛选、评分、解释和执行
- [ ] 做一张“数据字段 → Agent 模块 → 用途”的对应表

### 4. 系统设计说明

- [ ] 画出系统整体流程图
- [ ] 说明 parser、planner、scorer、executor、explainability 各模块职责
- [ ] 说明 Qwenpaw 在系统中的位置
- [ ] 说明用户确认后如何进入预约、订位、点单流程

### 5. Demo 展示说明

- [ ] 准备 2-3 个固定展示案例
- [ ] 每个案例都要对应长者真实需求
- [ ] 截图保存 demo 输入、路线输出、推荐理由、执行结果
- [ ] 在报告中说明 demo 如何体现完整闭环

### 6. 局限与未来优化

- [ ] 说明当前数据仍有缺失，例如经纬度、真实餐厅接口、实时交通等
- [ ] 说明 Qwenpaw 真实执行能力需要继续验证
- [ ] 说明后续可加入更多澳门本地生活服务
- [ ] 说明未来可扩展到医院、药房、社区活动、康养路线等场景

## 二、Demo 修改

### 1. 页面文案修改

- [ ] 页面标题改为“银龄澳门本地生活 Agent”
- [ ] 输入提示改成长者出行场景
- [ ] 示例问题改成陪父母、爷爷奶奶、行动不便、喝茶吃点心等场景
- [ ] 输出结果强调低疲劳、少步行、少台阶、有休息点、有厕所、交通方便

### 2. 输入解析修改

- [ ] 增加长者相关字段识别
- [ ] 识别是否需要避免楼梯
- [ ] 识别是否需要少走路
- [ ] 识别是否需要无障碍厕所
- [ ] 识别是否需要休息点
- [ ] 识别是否偏好清淡饮食、喝茶、点心、餐厅订位
- [ ] 识别是否需要 Qwenpaw 执行预约、订位或点单

### 3. 路线规划修改

- [ ] 优先选择适老化评分高的地点
- [ ] 避开台阶多、坡度大、暴晒、步行距离长的路线
- [ ] 优先选择交通简单、下车后好走的路线
- [ ] 控制半日行程数量，不要安排太满
- [ ] 每条路线加入休息点和厕所提示

### 4. 推荐解释修改

- [ ] 每个推荐点都写清为什么适合长者
- [ ] 每条路线都写清步行、交通、休息、厕所、风险
- [ ] 不只输出景点名称，要输出推荐依据
- [ ] 风险提示要明确，例如台阶、拥挤、暴晒、距离较远

### 5. Qwenpaw 执行流程修改

- [ ] 设计预约任务格式
- [ ] 设计餐厅订位任务格式
- [ ] 设计点单任务格式
- [ ] 设计执行成功、失败、需要确认三种状态
- [ ] demo 中先保留 mock 执行结果，保证展示稳定
